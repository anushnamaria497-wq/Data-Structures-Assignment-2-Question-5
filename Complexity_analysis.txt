COMPLEXITY ANALYSIS
===================

1. TREE STRUCTURE

Number of departments = 7
Number of tree nodes = 8

Tree height = 3 edges

Number of levels = 4

The longest path is:

CEO -> IT -> Development -> Frontend

Tree storage:
Space Complexity = O(n)

Tree construction:
Time Complexity = O(n)


2. LEVEL-ORDER TRAVERSAL

Level-order traversal visits the nodes level by level
using a queue.

Traversal order:

CEO HR Finance IT Development Testing Frontend Backend

Time Complexity = O(n)

Auxiliary Space Complexity = O(n)


3. LINEAR SEARCH

Linear Search checks the department names one by one.

Best Case Time Complexity = O(1)

Average Case Time Complexity = O(n)

Worst Case Time Complexity = O(n)

Extra Space Complexity = O(1)


4. BINARY SEARCH

Binary Search works on sorted department names and
reduces the search range by half in each step.

Best Case Time Complexity = O(1)

Average Case Time Complexity = O(log n)

Worst Case Time Complexity = O(log n)

Extra Space Complexity = O(1)


5. SEARCH COMPARISON

Sorted Department List:

Backend, Development, Finance, Frontend, HR, IT, Testing

Observed comparisons:

Development:
Linear Search = 2
Binary Search = 2

HR:
Linear Search = 5
Binary Search = 3

Testing:
Linear Search = 7
Binary Search = 3


6. OVERALL ANALYSIS

The tree structure represents the organisational
hierarchy clearly.

Level-order traversal displays the hierarchy level
by level.

Linear Search does not require sorted data.

Binary Search requires sorted data but generally
requires fewer comparisons for larger datasets.

Therefore, a tree is suitable for organisational
reporting, while a sorted array with Binary Search
is suitable for department searching when the data
is maintained in sorted order.
